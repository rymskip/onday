# fix(dom): act on a page whose window is minimized or behind others

- **Date:** 2026-10-29 21:57
- **Commit:** eaf52be
- **Area:** actions

## Problem

In a headed browser, clicks and other pointer actions stopped working once the window was minimized or hidden behind other windows. Each one hung for 30s on `script.callFunction` and then retried until its timeout.

## Cause

The stability check samples the element's box over two animation frames. A document the browser treats as hidden renders no frames, so its `requestAnimationFrame` callbacks never run and the check's promise never settles. Chromium also marks a window covered by others as hidden and throttles its renderer and timers.

## Introduced

4f4099b (2026-10-21) `0.4.0: act on the page as Playwright does, and type into a field like a person`, which moved the stability check onto animation frames.

## Fix

The stability check waits for the next frame through `nextFrame`. While the document is hidden, or once it becomes hidden mid-wait, a 16ms timer stands in for the frame. Chromium launches with `--disable-backgrounding-occluded-windows`, `--disable-renderer-backgrounding` and `--disable-background-timer-throttling`, as Playwright does, so a covered window keeps rendering and its page stays visible.

## Verified

- New `*_clicks_in_a_hidden_window_*` tests launch headed, minimize the window, assert `document.visibilityState` is `hidden`, then click and check the result. Chromium over BiDi failed before the fix with the 30s `script.callFunction` timeout. Chromium over BiDi and Classic, and Firefox over BiDi, pass after it.
- `cargo test -p onday --test browser -- --ignored`: all 10 tests pass.
- `cargo fmt --check`, `cargo clippy --all-targets --all-features -- -D warnings` and `cargo test --all-features` are clean.
