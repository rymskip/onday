# feat(page): evaluate in onday's own world with inspect

- **Date:** 2026-10-18 14:16
- **Commit:** 60b3471
- **Area:** Page

## Problem

An application's e2e suite runs axe-core over every page a test leaves. On a large page of a dev build the audit ran past onday's 30-second command limit, and the browser answered nothing else until axe finished.

## Cause

`Page::evaluate` runs in the page's own world. The dev build there is Svelte's, which replaces `Array.prototype.indexOf`, `lastIndexOf` and `includes` with versions that rescan the array on every miss to warn about proxy equality. axe calls `indexOf` constantly, and a CPU profile put 33 of a 38-second audit inside Svelte's wrapper. onday already ran its own scripts in a sandbox world, out of the page's reach, but offered no way for a caller to do the same.

## Introduced

Not a regression: `evaluate` has always run in the page's world, which is the right default for a script that drives the page.

## Fix

`Page::inspect` evaluates like `evaluate`, in onday's sandbox. The script shares the document and keeps pristine globals, and the page cannot see what it defines. Over Classic, which has no sandbox, it runs in the page's world.

## Verified

The Chromium scenario patches `indexOf` in the page to throw, then checks that `evaluate` sees the patch while `inspect` reads `[1, 2].indexOf(2)` as 1, reads the document's title, and cannot see a global the page defined. `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --all-features -- -D warnings`, `cargo test --workspace --all-features`, and `cargo test -p onday --test browser -- --ignored chromium_over`, 2 passed.
