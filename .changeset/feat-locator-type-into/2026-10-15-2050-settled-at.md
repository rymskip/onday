# fix(events): record when a request settled by onday's own clock

- **Date:** 2026-10-15 20:50
- **Commit:** 405a31f
- **Area:** Events

## Problem

Every request in a network listing, answered or failed, reported a duration of 0ms, so a failure report could not say when a request finished or was cancelled.

## Cause

The duration was the settling event's `timestamp` minus the request's. Chromium over BiDi stamps every event of a request with the request's start, so the two were always equal.

## Introduced

e8050d3 (2026-09-12), "feat(onday): WebDriver BiDi browser automation and an MCP server", which took request timing from the event timestamps.

## Fix

A settled request records `settled_at`, the moment onday received its outcome, by onday's own clock, and its duration from that, the way Playwright's BiDi network manager stamps a failure it has no protocol time for. The unread protocol timestamps are gone. The MCP prints start and settle times, and no duration for a request still pending.
