# feat(events): keep a console message's whole stack

- **Date:** 2026-10-19 21:28
- **Commit:** 6d2e5e6
- **Area:** Events

## Problem

An application's e2e failed on a Svelte `derived_inert` warning whose only location was Vite's `@vite/client`, which named nothing about the code that warned, and the warning would not reproduce by hand.

## Cause

`log.entryAdded` carries the call's whole stack, and onday kept only its first frame as the message's `location`. Vite wraps `console` to forward the page's logs to the dev server, so that first frame is the wrapper for every message a dev page logs.

## Introduced

e8050d3 (2026-09-12, feat(onday): WebDriver BiDi browser automation and an MCP server) kept the first frame alone.

## Fix

`ConsoleMessage` gains `stack`, every frame innermost first as `url:line:column`. `location` stays the first frame, so Playwright's `ConsoleMessage.location()` keeps its meaning. A Classic session's messages carry no frames, as before.

## Verified

The browser scenario now logs its warning through a wrapper function and requires at least three frames over BiDi, the first of them the location. `cargo test -p onday --test browser chromium_over -- --ignored` passed both Chromium sessions, BiDi and Classic.
