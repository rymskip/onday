# fix(page): move a frame to a fresh sandbox when the driver loses onday's

- **Date:** 2026-10-14 22:56
- **Commit:** 0ee6342
- **Area:** Page

## Problem

Typing into Stripe's split card fields failed after the runtime moved into a sandbox: resolving the card number input answered `script.callFunction: unknown error — Internal assertion failed` on every attempt until the 60-second budget ran out.

## Cause

On that page, chromedriver answered every `script.callFunction` into the `onday` sandbox of the card number frame with that internal assertion, while the same call into a sandbox under any other name in the same frame, and into every other frame's `onday` sandbox, answered at once. Probed over BiDi on the live page with `() => 1 + 1`. What put the frame's `onday` sandbox in that state was not established: a fixture frame resolved while blank and then navigated cross-origin did not reproduce it.

## Introduced

56348d7 (2026-10-14), "fix(page): run the runtime in a sandbox the page cannot reach", which first sent runtime calls to a named sandbox.

## Fix

A runtime-world call that fails with the driver's `unknown error` moves its frame to a sandbox with a fresh name (`onday-1`, `onday-2`, …), counted per browsing context on the page, and is sent once more. The fresh sandbox holds no runtime, so a runtime call answers that it is missing and the runtime is installed there, as in any new document.

## Verified

`cargo test -p onday --test browser chromium -- --ignored`: all four Chromium scenarios pass, as do clippy with `-D warnings` and the unit tests. No test in this repository reproduces the lost sandbox. In an application's e2e suite, a test that failed on it twice running then typed into the card frame and passed with this change.
