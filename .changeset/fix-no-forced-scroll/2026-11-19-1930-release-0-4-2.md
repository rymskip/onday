# chore(release): 0.4.2

- **Date:** 2026-11-19 19:30
- **Commit:** 10f66aa
- **Area:** Release

## Problem

The forced-scroll fix reaches a project that pins onday from crates.io only in a published
release, and 0.4.1 is already published.

## Cause

The workspace was still at 0.4.1.

## Introduced

none

## Fix

The workspace version and the `onday` workspace dependency onday_mcp builds against are 0.4.2,
and `Cargo.lock` follows. Tagging the merged commit `v0.4.2` publishes both crates.

## Verified

`cargo update --workspace --offline` moved only onday and onday_mcp to 0.4.2.
`cargo publish --workspace --locked --dry-run` packaged and verified onday 0.4.2 and then
onday_mcp 0.4.2 and stopped before uploading, with no other warning.
